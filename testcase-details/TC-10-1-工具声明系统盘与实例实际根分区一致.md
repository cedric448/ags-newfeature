# TC-10-1 工具声明系统盘，实例实际根分区与声明一致

| 项 | 值 |
|---|---|
| 用例编号 | TC-10-1 |
| 所属测试例 | TC-10 系统盘（Resources.Storage）真实生效验证 |
| 优先级 | P0 |
| 类型 | 正向 / 数据一致性 |
| 结论 | **PASS** |

## 测试目的

验证 `CreateSandboxTool` 的 `CustomConfiguration.Resources.Storage` 声明值，
是否真实反映到沙箱内根分区 `/` 的实际容量上。

> 核心：接口回显 `Storage` 只能证明「参数被接受」，不能证明「磁盘被真实分配」。
> 必须进入沙箱执行 `df` / `findmnt` 才能证明系统盘真实被拉起。

## 前置条件

- 地域 `ap-beijing`，账号系统盘上限 **150Gi**（已开通，未开通默认为 20Gi）
- 镜像具备 envd（端口 49983），健康检查 `/health`
- 工具类型 `custom`，网络模式 `SANDBOX`

## 测试步骤

1. `CreateSandboxTool`，`Resources.Storage` 依次取 `1Gi / 20Gi / 50Gi / 100Gi / 150Gi`
2. 等待工具 `ACTIVE`
3. `StartSandboxInstance`，**不传** `CustomConfiguration`（沿用工具声明）
4. 等待实例 `RUNNING`
5. 进入沙箱执行 `df -B1 / | tail -1` 与 `findmnt -no SOURCE,FSTYPE,SIZE /`
6. 比对实测字节数与声明值

## 预期结果

根分区实际容量 ≈ 声明值，允许文件系统元数据开销（实测恒小于声明值）。

## 实际结果

| 声明 | 接口回显 | `df -h /` 实测 | 偏差 | 结论 |
|---|---|---|---|---|
| 1Gi | 1Gi | 973.4M | -5.0%（-51 MiB） | PASS |
| 20Gi | 20Gi | 19.52Gi | -2.4%（-492 MiB） | PASS |
| 50Gi | 50Gi | 48.91Gi | -2.2%（-1116 MiB） | PASS |
| 100Gi | 100Gi | 97.87Gi | -2.1%（-2181 MiB） | PASS |
| 150Gi | 150Gi | 148.68Gi | -0.9%（-1352 MiB） | PASS |

**结论：5 个档位全部与实际根分区容量一致，系统盘真实被拉起。**

## 观察

1. 实测值**恒小于**声明值，符合文档「文件系统开销，略小于声明值」的描述；
2. 小档位相对偏差更大：1Gi 档偏 5%，150Gi 档仅 0.9% —— 这是固定元数据开销导致的，
   不是容量分配错误；
3. 根分区 `findmnt` 显示为 `overlay2 / overlay`，与文档示例一致。

## 备注

- 100Gi 档实测偏差绝对值最大（-2181 MiB），约 2.1%，仍在合理范围；
- 若账号未开通更大配额，`Storage` 超过 20Gi 会报 `InvalidParameterValue`，
  报错信息会给出本账号实际可用档位（见 TC-10-4）。
