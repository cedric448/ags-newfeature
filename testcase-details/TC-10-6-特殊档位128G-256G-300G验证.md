# TC-10-6 特殊档位 128Gi / 256Gi / 300Gi 验证

| 项 | 值 |
|---|---|
| 用例编号 | TC-10-6 |
| 所属测试例 | TC-10 系统盘真实生效验证 |
| 优先级 | P1 |
| 类型 | 正向 + 负例 / 档位规则 |
| 结论 | ✅ **PASS** —— 128Gi 真实生效；256/300Gi 受账号上限拦截 |

## 测试目的

文档规定档位规则为「1–100Gi 按 1Gi 递增；105–300Gi 按 5Gi 递增；**另有 128Gi、256Gi**」。
本用例专门验证这几个**特殊档位**（不落在常规递增序列上的值）的实际行为。

## 前置条件

- 账号 `ap-beijing` 系统盘上限 **150Gi**（已开通）
- 因此 128Gi 在上限内可用，256Gi / 300Gi 超出上限

## 测试结果

### 档位可用性（接口层）

| 档位 | 是否合法档位 | 本账号是否可用 | 实际返回 |
|---|---|---|---|
| **128Gi** | ✅ 特殊档 | ✅ 可用 | `ACCEPTED` |
| **256Gi** | ✅ 特殊档 | ❌ 超上限（150Gi） | `InvalidParameterValue` |
| **300Gi** | ✅ 合法（105–300 区间上界） | ❌ 超上限（150Gi） | `InvalidParameterValue` |
| 105Gi | ✅（105 起按 5Gi 递增） | ✅ 可用 | `ACCEPTED` |
| 110Gi | ✅ | ✅ 可用 | `ACCEPTED` |
| 151Gi / 160Gi | ✅ 档位本身合法 | ❌ 超上限 | `InvalidParameterValue` |

### 128Gi 及相邻档位的实际分配

| 声明 | 接口回显 | 精确字节数 | `df` 实测 | 偏差 | 结论 |
|---|---|---|---|---|---|
| 105Gi | 107520Mi | 112,064,000,000 附近 | 104.37 GiB | -0.60% | ✅ PASS |
| 110Gi | 112640Mi | — | 109.29 GiB | -0.65% | ✅ PASS |
| **128Gi** | 131072Mi | **137,438,953,472** | **128.00 GiB** | **0.00%** | ✅ PASS |

### 256Gi / 300Gi 报错详情

```
[InvalidParameterValue] DiskSize "256Gi" exceeds the system disk limit 150Gi
of this account in region ap-beijing;
allowed: 1-100 (1Gi step), 105-300 (5Gi step), or 128/256 up to 150Gi
```

```
[InvalidParameterValue] DiskSize "300Gi" exceeds the system disk limit 150Gi
of this account in region ap-beijing;
allowed: 1-100 (1Gi step), 105-300 (5Gi step), or 128/256 up to 150Gi
```

两者错误信息一致，且明确提示「`or 128/256 up to 150Gi`」——
**说明 128Gi 被识别为特殊档位**，而 256Gi 需要上限提升到 256Gi 才可用。

## 关键发现

### 1. 128Gi 精确对齐，偏差为 0

128Gi 档实测 **137,438,953,472 字节 = 128 × 2³⁰ = 2³⁷**，**分毫不差**。

对比其他档位的偏差：

| 档位 | 实测字节数 | 与声明的关系 |
|---|---|---|
| 20Gi | 20,957,446,144 | ≈ 20 × 10⁹（十进制 GB） |
| 50Gi | 52,521,566,208 | ≈ 50 × 10⁵（十进制） |
| 128Gi | **137,438,953,472** | **= 128 × 2³⁰（二进制 GiB 精确匹配）** |

**解释**：常规档位按**十进制 GB**（10⁹）分配，因此按 GiB 统计时偏小约 2%；
而 128Gi 恰好是 2 的整数次幂，十进制与二进制在此收敛，故偏差为 0。

> 这解释了为什么 `df -h` 在 20Gi 档显示 `20G` 但精确值只有 19.52GiB ——
> 是**单位换算差异**，不是容量少给。

### 2. 特殊档位确实独立于递增序列存在

128Gi 位于 105–300Gi 按 5Gi 递增的序列之外（125、130 才是序列值），
但其被接受，证明文档中「**另有 128Gi**」的描述准确。

### 3. 超上限时错误信息统一且可操作

256Gi、300Gi 与 999Gi 返回**完全相同格式**的错误，并在末尾给出账号实际上限，
用户可直接据此判断「需要提工单提升上限」还是「改用档位内的值」。

## 结论

| 检查项 | 结论 |
|---|---|
| 128Gi 特殊档可用且真实分配 | ✅ 精确 128.0 GiB |
| 256Gi 在 150Gi 上限账号下被拒 | ✅ 报错清晰 |
| 300Gi 在 150Gi 上限账号下被拒 | ✅ 报错清晰 |
| 105Gi / 110Gi 5Gi 递增档可用 | ✅ 真实分配 |

**128Gi / 256Gi 作为特殊档位真实存在；在本账号 150Gi 上限下，
128Gi 可正常使用且分配精确，256Gi / 300Gi 需提升账号上限后方可使用。**

## 备注

- 若需验证 256Gi / 300Gi 的真实分配，需要将账号上限提升至 256Gi / 300Gi
- `128Gi` 与 `256Gi` 的错误提示中均被单独列为特殊档，与文档一致
