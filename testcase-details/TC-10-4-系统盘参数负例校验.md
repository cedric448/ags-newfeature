# TC-10-4 系统盘参数负例校验

| 项 | 值 |
|---|---|
| 用例编号 | TC-10-4 |
| 所属测试例 | TC-10 系统盘真实生效验证 |
| 优先级 | P0 |
| 类型 | 负例 / 参数校验 |
| 结论 | **PASS（4/4 全部按预期被拒）** |

## 测试目的

验证非法 `Storage` 取值在**创建阶段**就被拒绝，而不是等到启动实例才失败。

## 测试结果

| 场景 | 输入 | 预期错误码 | 实际结果 | 结论 |
|---|---|---|---|---|
| 超过账号上限 | `999Gi` | `InvalidParameterValue` | 拒绝：`DiskSize "999Gi" exceeds the system disk limit 150Gi of this account in region ap-beijing` | PASS |
| 不在可选档位 | `103Gi` | `InvalidParameterValue` | 拒绝：`DiskSize must be one of: 1-100 (1Gi step), 105-300 (5Gi step), or 128/256` | PASS |
| 单位格式错误 | `50G` | `InvalidParameterValue` | 拒绝：同上 `must be one of` | PASS |
| 只传 Storage 缺 CPU | `Resources={Storage:20Gi}` | `InvalidParameter` | 拒绝：`Resources: CPU is required` | PASS |

## 关键观察

1. **超上限错误信息友好**：直接告知本账号在该地域的实际上限（150Gi）和可选档位区间，
   用户可据此自行调整，无需提工单询问；
2. **档位规则被严格执行**：`103Gi` 落在 100–105 的空隙，被正确拒绝；
   说明实现严格遵循「1–100Gi 按 1Gi 递增，105–300Gi 按 5Gi 递增」；
3. **单位严格校验**：`50G`（缺少 `i`）被拒，符合文档「只接受 `<正整数>Gi`」；
4. **Resources 整体覆盖的强约束**：只传 `Storage` 时 `CPU`/`Memory` 必须一并提供，
   这是实例级覆盖的一个易踩坑点。

## 完整错误信息（超上限）

```
[InvalidParameterValue] DiskSize "999Gi" exceeds the system disk limit 150Gi
of this account in region ap-beijing;
allowed: 1-100 (1Gi step), 105-300 (5Gi step), or 128/256 up to 150Gi
```

## 备注

负例均在 `CreateSandboxTool` 阶段返回，未产生残留资源。
